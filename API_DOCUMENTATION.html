NavzaBD API Reference

Complete REST API documentation for the NavzaBD e-commerce backend. All endpoints, parameters, request bodies, and expected responses are documented below.

📦 Version 1.0.0
🔐 Auth JWT Bearer Token
🗄️ Database MongoDB
⚡ Runtime Node.js + Express

Access Levels

Public

No authentication required. Open to all requests.

Protected

Requires a valid JWT token in the Authorization header.

Admin only

Requires JWT token with admin role. Standard users are rejected.

Webhook

Called by external services (e.g., Stripe). No user token needed.

Authentication

/api/auth

Handles user registration, login, logout, and profile retrieval. Login returns a JWT token that must be included in the Authorization: Bearer <token> header for all protected routes.

POST /api/auth/register Public Register a new user ▼

Creates a new user account. Passwords are hashed before storage. Returns the created user object on success.

Request Body · application/json
FieldTypeRequiredDescription
namestringrequiredFull name of the user.
emailstringrequiredMust be a valid, unique email address.
passwordstringrequiredPlain text password. Will be hashed server-side.
Example Request
"name": "Mahedi Zaman", "email": "mahedi@example.com", "password": "securepassword123"
Responses
201 Created User successfully registered.
400 Bad Request Missing fields or email already in use.
POST /api/auth/login Public Authenticate and get token ▼

Validates credentials and returns a signed JWT token. The token should be stored client-side and sent with all subsequent protected requests via the Authorization: Bearer <token> header.

Request Body · application/json
FieldTypeRequiredDescription
emailstringrequiredRegistered email address.
passwordstringrequiredAccount password (plain text, compared to hash).
Example Response · 200 OK
"token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "user": { "_id": "64f2a...", "name": "Mahedi Zaman", "email": "mahedi@example.com", "role": "user" }
Responses
200 OK Login successful. Returns JWT token and user data.
401 Unauthorized Invalid email or password.
POST /api/auth/logout Protected Invalidate current session ▼

Invalidates the current user session by clearing the token cookie. After calling this endpoint, the token is no longer valid for subsequent requests.

Request Headers
HeaderValueRequired
AuthorizationBearer <token>required
Responses
200 OK Session cleared successfully.
401 Unauthorized Token missing or invalid.
GET /api/auth/profile Protected Get current user profile ▼

Returns the full profile data of the currently authenticated user, decoded from the JWT token. Password field is excluded from the response.

Request Headers
HeaderValueRequired
AuthorizationBearer <token>required
Example Response · 200 OK
"_id": "64f2a...", "name": "Mahedi Zaman", "email": "mahedi@example.com", "role": "user", "addresses": [], "createdAt": "2025-01-01T00:00:00.000Z"

Products

/api/products

Full CRUD for products. Public users can browse and search. Only admins can create, update, or delete. Authenticated users can submit ratings.

GET /api/products Public List all products with filters ▼

Returns a paginated list of all products. Supports filtering by category, brand, and price range. Results can be sorted and searched by keyword.

Query Parameters
ParameterTypeRequiredDescription
pagenumberoptionalPage number for pagination. Default: 1.
limitnumberoptionalNumber of results per page. Default: 10.
sortOrderstringoptionalSort direction: asc or desc.
categorystringoptionalFilter by category ID or slug.
brandstringoptionalFilter by brand ID or slug.
priceMinnumberoptionalMinimum price filter.
priceMaxnumberoptionalMaximum price filter.
searchstringoptionalKeyword search against product name and description.
Example URL
GET /api/products?page=1&limit=12&category=chips&sortOrder=asc&priceMin=5&priceMax=50
POST /api/products Admin only Create a new product ▼

Creates one or multiple products. Accepts either a single JSON object, a JSON array for bulk creation, or multipart/form-data to include an image file upload in the same request.

Request Body · application/json
FieldTypeRequiredDescription
namestringrequiredProduct name.
descriptionstringrequiredProduct description.
pricenumberrequiredPrice in base currency.
categoryIdstringrequiredMongoDB ObjectId of the category.
brandIdstringrequiredMongoDB ObjectId of the brand.
discountPercentagenumberoptionalDiscount percentage (0–100).
stocknumberoptionalAvailable stock quantity. Default: 0.
imagestring | fileoptionalImage URL (JSON) or file upload (FormData).
GET /api/products/:id Public Get single product by ID ▼

Returns a single product by its MongoDB ObjectId. The response includes fully populated category and brand objects (not just IDs).

Path Parameters
ParameterTypeDescription
idstringMongoDB ObjectId of the product.
PUT /api/products/:id Admin only Update a product ▼

Updates an existing product's fields. All fields are optional — only provided fields are updated. Supports both JSON and multipart/form-data for image replacement.

Request Body (all fields optional)
FieldTypeDescription
namestringUpdated product name.
descriptionstringUpdated description.
pricenumberUpdated price.
stocknumberUpdated stock quantity.
discountPercentagenumberUpdated discount.
categoryIdstringUpdated category reference.
brandIdstringUpdated brand reference.
imagestring | fileNew image URL or file upload.
DELETE /api/products/:id Admin only Delete a product ▼

Permanently removes a product from the database by its ID. This action is irreversible.

Path Parameters
ParameterTypeDescription
idstringMongoDB ObjectId of the product to delete.
Responses
200 OK Product deleted successfully.
401 Unauthorized Token missing or not admin.
POST /api/products/:id/rate Protected Rate a product ▼

Allows an authenticated user to submit a rating (and optional comment) for a product. If the user has already rated the product, the existing rating is updated instead of creating a duplicate.

Request Body · application/json
FieldTypeRequiredDescription
ratingnumberrequiredRating value between 1 and 5.
commentstringoptionalOptional review text.

Orders

/api/orders

Manages the full order lifecycle — from creation to fulfillment. When an order is placed, product stock is automatically decremented. Admins have additional access to all orders and fulfillment controls.

POST /api/orders Protected Place a new order ▼

Creates a new order from the user's cart. On success, the stock of each ordered product is decremented accordingly. Requires a valid shipping address and a list of order items.

Request Body · application/json
FieldTypeRequiredDescription
orderItemsarrayrequiredArray of items: [{ productId, name, price, quantity, image? }]
shippingAddressobjectrequired{ street, city, country, postalCode }
paymentMethodstringoptionale.g., "stripe", "cod".
Responses
201 Created Order placed. Returns the full order object.
400 Bad Request Insufficient stock or missing fields.
GET /api/orders Protected Get orders for current user ▼

Returns all orders belonging to the authenticated user. If the user has an admin role, this endpoint returns all orders in the system instead.

GET /api/orders/admin Admin only Get all orders (admin view) ▼

Returns a complete list of all orders in the system with user details populated. Intended for the admin dashboard and order management panel.

PUT /api/orders/:id/status Protected Update order status ▼

Updates the primary status of an order. Available statuses are pending, paid, completed, and cancelled.

Request Body · application/json
FieldTypeValues
statusstringpending · paid · completed · cancelled
PUT /api/orders/:id/fulfillment Admin only Update fulfillment status ▼

Updates the fulfillment/shipping status of an order. Used by admins to track physical delivery progress from the warehouse to the customer.

Request Body · application/json
FieldTypeValues
fulfillmentStatusstringpending · processing · shipped · delivered
PUT /api/orders/:id/webhook-status Webhook Update status from webhook ▼

Called by external services like Stripe to update order status after a payment event. No user authentication is required — this endpoint is intended for server-to-server communication only.

Request Body · application/json
FieldTypeValues
statusstringpending · processing · shipped · delivered · cancelled

Cart

/api/cart

Manages the user's shopping cart. Each user has a single cart document. Items can be added, updated, or removed individually, or the entire cart can be cleared at once.

GET /api/cart Protected Get current user's cart ▼

Returns the authenticated user's cart document, including all items and the calculated total price.

Example Response · 200 OK
"items": [ { "productId": "64f2a...", "name": "Crunchy Banana Chips", "price": 7, "quantity": 2, "image": "https://..." } ], "totalPrice": 14
POST /api/cart Protected Add or update item in cart ▼

Adds a product to the cart. If the product already exists in the cart, its quantity is updated to the provided value instead of adding a duplicate entry.

Request Body · application/json
FieldTypeRequiredDescription
productIdstringrequiredMongoDB ObjectId of the product.
quantitynumberrequiredQuantity to add. Must be greater than 0.
PUT /api/cart/update Protected Update item quantity ▼

Updates the quantity of a specific product already in the cart. Use this for increment/decrement controls in the cart UI.

Request Body · application/json
FieldTypeRequiredDescription
productIdstringrequiredMongoDB ObjectId of the product to update.
quantitynumberrequiredNew quantity value.
DELETE /api/cart/:productId Protected Remove a single item ▼

Removes a specific product from the cart by its ID. Other items in the cart remain unaffected.

Path Parameters
ParameterTypeDescription
productIdstringMongoDB ObjectId of the product to remove.
DELETE /api/cart Protected Clear entire cart ▼

Removes all items from the user's cart at once. The cart document itself is retained but all items are cleared. Useful after a successful order placement.

Responses
200 OK Cart cleared successfully.

Payments

/api/payments · /api/payment

Stripe payment integration supporting two flows: Payment Intent (for card-based flows) and Checkout Session (for hosted redirect flows). Note that /api/payments/... and /api/payment/... are separate namespaces handling different flows.

POST /api/payments/create-intent Protected Create Stripe Payment Intent ▼

Creates a Stripe Payment Intent for a specific order. Returns a clientSecret that the frontend uses to complete the payment via Stripe.js or Stripe Elements.

Request Body · application/json
FieldTypeRequiredDescription
orderIdstringrequiredMongoDB ObjectId of the order to pay for.
amountnumberrequiredAmount in smallest currency unit (e.g., cents for USD).
currencystringoptionalISO currency code. Default: "usd".
Example Response · 200 OK
"clientSecret": "pi_3NqX...secret_abc123"
POST /api/payment/initiate Protected Create Stripe Checkout Session ▼

Creates a Stripe Checkout Session and returns a hosted payment page URL. The frontend redirects the user to this URL to complete payment on Stripe's hosted page.

Request Body · application/json
FieldTypeRequiredDescription
amountnumberrequiredTotal amount for the session.
itemsarrayrequiredArray of line items for the checkout session.
shippingAddressobjectrequiredDelivery address object.
Example Response · 200 OK
"url": "https://checkout.stripe.com/c/pay/cs_live_..."
GET /api/payment/verify Public Verify checkout session ▼

Verifies whether a Stripe Checkout Session was completed successfully. Called as the return URL handler after Stripe redirects the user back to your app.

Query Parameters
ParameterTypeDescription
session_idstringStripe Checkout Session ID, automatically appended by Stripe to the return URL.
POST /api/payments/webhook Webhook · Stripe Handle Stripe webhook events ▼

Receives and processes Stripe webhook events (e.g., payment_intent.succeeded, checkout.session.completed). Automatically updates the corresponding order and payment status in the database. The raw request body must be forwarded unmodified for signature verification.

Request Headers
HeaderDescription
stripe-signatureStripe webhook signature for payload verification. Must not be modified.
⚠️ Important
// Express must receive the raw body for Stripe signature verification. // Do NOT use express.json() middleware on this route. // Use express.raw({ type: 'application/json' }) instead.

Analytics

/api/analytics

All analytics endpoints are restricted to admin users and return aggregated data for use in the admin dashboard — overview cards, product performance, sales trends, and inventory alerts.

GET /api/analytics/overview Admin only Platform overview stats ▼

Returns high-level platform metrics including total registered users, total products, total orders placed, and cumulative revenue. Designed for the top summary cards of the admin dashboard.

Example Response · 200 OK
"totalUsers": 1240, "totalProducts": 348, "totalOrders": 892, "totalRevenue": 48750.00
GET /api/analytics/products Admin only Product performance analytics ▼

Returns product-level analytics including the top-selling products by order volume and a list of products with critically low stock levels.

GET /api/analytics/sales Admin only Sales data over time ▼

Returns time-series sales data broken down by day and month, including revenue totals and order counts. Used to populate line charts and bar charts in the admin dashboard.

GET /api/analytics/inventory-alerts Admin only Low stock & out-of-stock alerts ▼

Returns a list of products that are either low in stock (below threshold) or completely out of stock. Used for inventory alert notifications in the admin panel.

Stats

/api/stats

Quick summary statistics endpoint for the admin dashboard.

GET /api/stats Admin only Dashboard summary ▼

Returns a condensed summary of key platform metrics — total users, products, orders, and revenue. Similar to /api/analytics/overview but optimized for fast dashboard card rendering.

Example Response · 200 OK
"totalUsers": 1240, "totalProducts": 348, "totalOrders": 892, "totalRevenue": 48750.00
