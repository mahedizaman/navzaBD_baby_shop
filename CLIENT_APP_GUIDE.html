Checkout & Payment

Route: /checkout · Component: client/app/checkout/page.tsx

Required Fields

Before payment can be initiated, all four shipping address fields must be filled in.

FieldRequiredNotes
streetrequiredStreet address line
cityrequiredCity name
countryrequiredCountry name or code
postalCoderequiredZIP or postal code
If any field is missing when the user clicks Pay Now, a toast.error("Please fill in all shipping address fields.") is shown and the request is not sent.

Note: Phone number is not currently required. It can be added to both the form and the API request body if needed.
Authentication

The checkout page reads a JWT token from localStorage using getStoredAuthToken() (keys: token or navzabd_token). If no token is found, a toast.error prompts the user to log in.

⚠️ Local testing only: You can temporarily bypass the token check by commenting out the if (!token) block in checkout/page.tsx. Never do this in production — the backend route POST /api/payment/initiate is protected and requires a valid JWT.
Payment Flow

Step-by-step breakdown of what happens when the user clicks Pay Now.

1

User fills in shipping details and clicks Pay Now

handlePayNow() builds the request body: amount (cart total), items (array of { productId, name, price, qty, image }), and shippingAddress.

2

Frontend sends request to backend

Calls POST /api/payment/initiate with the JWT token via initiatePayment(body, token) from the services layer.

3

Backend processes the request

Validates amount and stock availability → creates an Order document with status: pending → creates a Stripe Checkout Session → returns { url, sessionId, orderId }.

4

Frontend redirects to Stripe

window.location.href = url — the user is sent to the Stripe hosted checkout page to complete payment.

5

Stripe redirects back

Success: /payment/success?session_id=...
Failure / Cancel: /payment/fail

6

Optional: Verify payment

The success page can call GET /api/payment/verify?session_id=... to confirm the order was marked as paid in the database.

Running Locally

Project root: /home/ra-one/website/Complete NavzaBD Baby Shop

Step 1 — Start the Backend
bashserver/
cd "server" npm install npm run dev # runs on port 8000
server/.env
PORT=8000 MONGO_URI=your_mongodb_uri JWT_SECRET=your_jwt_secret STRIPE_SECRET_KEY=your_stripe_secret_key STRIPE_WEBHOOK_SECRET=your_stripe_webhook_secret PUBLISHABLE_KEY=your_stripe_publishable_key STRIPE_CURRENCY=usd CLOUDINARY_CLOUD_NAME=your_cloudinary_cloud_name CLOUDINARY_API_KEY=your_cloudinary_api_key CLOUDINARY_API_SECRET=your_cloudinary_api_secret ADMIN_URL=http://localhost:5173 CLIENT_URL=http://localhost:3000 PRODUCTION_SERVER_URL=
Step 2 — Start the Client App
bashclient/
cd "client" npm install npm run dev # runs on http://localhost:3000
client/.env.local
NEXT_PUBLIC_API_URL=http://localhost:8000
This allows the Axios service layer to route all API calls to the correct backend URL. Configure your services/api.ts to read from process.env.NEXT_PUBLIC_API_URL.
