Login & Navigation

The admin panel requires a user account with role: "admin" set in the database. Standard user accounts cannot log in.

Logging In
1

Start the admin panel

Run npm run dev in the admin directory, then open http://localhost:5173 in your browser.

2

Enter your credentials

Use the email and password of a user with role: "admin" set in MongoDB.

3

Successful login

The backend returns a token and user object. These are saved to localStorage as admin_token and admin_user. The app then redirects you to /dashboard.

Dashboard Overview

The dashboard at /dashboard fetches data from GET /api/stats and displays key metrics and charts.

💰 Total Revenue

Cumulative sales revenue across all orders.

📦 Total Orders

Total number of orders placed on the platform.

🛍️ Total Products

Number of active products in the catalog.

👥 Total Users

Total registered user accounts.

A pie or donut chart provides a visual distribution analysis of these metrics.

Product Management

Manage your full product catalog from /dashboard/product. Products are displayed in a table with Name, Category, Brand, Price, and Stock columns.

Data source: GET /api/products?page=1&limit=500&sortOrder=desc — Category and brand fields are fully populated (names shown, not raw IDs).

Client-side validation runs first. If any required field is empty, a toast.error is shown. Otherwise, a FormData payload is sent to POST /api/products. The backend uploads the image via Multer to Cloudinary, then returns the created product. A toast.success("Product created.") confirms success and the list refreshes.

Editing and Deleting

✏️ Edit

Click Edit in the Actions column. A modal opens with current values pre-filled. Update any fields or upload a new image, then submit. Calls PUT /api/products/:id.

🗑️ Delete

Click Delete → confirm in the browser dialog. Calls DELETE /api/products/:id. On success, the list updates and a toast notification appears.

Orders & Invoices
Orders Management · /dashboard/order

Fetches all orders via GET /api/orders (admin sees all) and stats via GET /api/stats. The table displays Order ID, Customer, Items Summary, Amount, Payment Status, and Fulfillment Status.

Updating Fulfillment Status

Select a new status from the dropdown in any order row. This calls PUT /api/orders/:id/fulfillment and refreshes the data on success.

pending processing shipped delivered
Invoice Section · /dashboard/invoices

Invoice data is pulled from GET /api/orders. Each row shows Order ID, Customer Name, Date, Total Amount, and Payment Status.

📥 PDF Download

Each row has a Download button. Clicking it generates a PDF client-side using jsPDF containing:

— Header: NavzaBD Invoice
— Fields: Order ID, Customer name, Date
— Items table: Product name, Quantity, Line total
— Footer: Grand total and payment status

A "Invoice downloaded." Sonner toast confirms the action. All tables use overflow-x-auto for mobile compatibility.

Running Locally

Project root: /home/ra-one/website/Complete NavzaBD Baby Shop

Step 1 — Start the Backend
bashserver/
cd "server" npm install npm run dev # runs on port 8000
server/.env
PORT=8000 MONGO_URI=your_mongodb_uri JWT_SECRET=your_jwt_secret STRIPE_SECRET_KEY=your_stripe_secret_key STRIPE_WEBHOOK_SECRET=your_stripe_webhook_secret PUBLISHABLE_KEY=your_stripe_publishable_key STRIPE_CURRENCY=usd CLOUDINARY_CLOUD_NAME=your_cloudinary_cloud_name CLOUDINARY_API_KEY=your_cloudinary_api_key CLOUDINARY_API_SECRET=your_cloudinary_api_secret ADMIN_URL=http://localhost:5173 CLIENT_URL=http://localhost:3000 PRODUCTION_SERVER_URL=
Step 2 — Start the Admin Panel
bashadmin/
cd "admin" npm install npm run dev # runs on http://localhost:5173
admin/.env
VITE_API_URL=http://localhost:8000
This tells the Axios client to route all /api/... calls to the backend server at port 8000.
